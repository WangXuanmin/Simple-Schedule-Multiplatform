## 1. 分步优化与结果

| 步骤 | 改动 | 对应结果 |
| --- | --- | --- |
| 本地事务（上一轮基础） | Web 同一 IndexedDB 事务保存任务和队列；Windows 单条 SQL 配合触发器原子保存 | 故障回滚、重启保留队列通过；网络挂起时本地操作仍可完成 |
| 服务端版本 | tasks 增加 version；RPC 同事务校验基准版本、更新任务并递增版本 | 真实并发同版本写入一成功一冲突；快／慢设备时间不能绕过 RPC |
| 请求去重 | 账号＋请求 UUID 对应持久回执；保存原始基准、内容及结果 | 重放返回原确认版本，不能改用同一 ID 提交不同内容；并发相同新增不重复落库 |
| 队列升级 | Web／Windows 保存基准版本、后继依赖和持久冲突 | 云端确认与本地清队列之间崩溃可重放；只推进尚未发送的后继请求，不自动强行重发冲突 |
| 原子确认 | 确认队列、写入云端版本、推进依赖在同一本地事务内完成 | IndexedDB／SQLite 中途故障全部回滚；较早确认保留后续本地草稿 |
| 冲突交互 | 两端提供“采用云端（放弃本地修改）”与“保留本地为新任务” | 冲突内容持久保存；另存副本使用新 ID，并保留原云端内容；已知冲突不阻塞其他任务上传 |
| 旧库与旧修改 | Windows 增量加列；缺少基准的旧离线修改提示选择，禁止拉取版本后直接覆盖 | 通过实际存储模块升级旧 SQLite 库，原任务、队列和失败记录保留；可另存草稿并确认上传 |
| 拉取与账号隔离 | 有待同步修改时缓存不覆盖；已知服务端版本优先于设备时间；异步 UI 再次核对当前账号 | 本地故障测试和真实跨账号 RPC／RLS 测试通过 |
| 兼容部署 | 新增 RPC，不撤销旧写入；展示 strict=false 提示；另备严格权限和墓碑保留脚本 | 真实旧式新增／更新仍正常且自动递增版本；严格脚本尚未执行 |
| 构建与文档 | 补充本地／真实云端复现脚本，更新协议、数据模型、状态与清单 | 类型检查、两个前端构建、Windows 原生 release 编译通过；未发布新客户端 |

SQLite 原子流程通过触发器绑定在一条语句中，不依赖连接池中多次 BEGIN／COMMIT 调用落到同一连接。测试使用生产 SQL；旧库升级测试还运行了实际 localDb 模块和已安装的 SQL 插件 JavaScript，仅以真实 Node SQLite 替换原生 IPC。

## 2. 已执行验证

环境：Windows、Node v24.15.0、本机 Chromium、项目依赖。两类浏览器／服务测试分别执行：

| 命令／范围 | 结果 |
| --- | --- |
| `npm test` | 24 项通过：共享核心／协议 13、Windows SQLite／旧库升级 11 |
| `npm run test:web` | 12 项 Chromium 检查通过：本地事务、确认回滚、重开恢复、上传挂起、断网重连、冲突副本等；云端请求被隔离模拟 |
| `npm run check` | 上述单元／SQLite 测试、类型检查、Web 与 Windows 前端构建通过 |
| `npm run test:supabase` | 在真实 PostgreSQL 检查 RPC、回执、旧版本、删除、跨账号／匿名访问及临时严格权限；事务最终回滚 |
| `npm run test:supabase:live` | 9 项真实 Auth／PostgREST 场景通过，包括并发写入、响应重放、账号隔离、隐式恢复拒绝和旧客户端兼容 |
| `npm run tauri:build -w @simple-schedule/windows -- --no-bundle` | Windows 原生 release 编译通过；不含 MSI／NSIS 安装包与原生界面完整验收 |

真实 HTTP 测试使用两个临时账号，测试后删除账号并级联清理任务／回执；不使用日常账号任务做修改实验。管理凭据仅在已登录的专用浏览器标签页中使用，不写入源码、日志或前端配置。

补充：测试和清理成功后，最后一次管理 API 只读复核因控制台会话返回“JWT failed verification”未完成；没有据此声称再次核对了全库数量。继续管理 API 操作前需恢复有效控制台登录，此前成功的迁移与测试结果不受影响。

为便于本地启动，Web／Windows 已从各自 .env.example 创建被 Git 忽略的 .env.local，仅含项目已有公开连接参数。本地 Windows 程序输出：`apps/windows/src-tauri/target/release/simple-schedule-windows.exe`。

复现说明：

- Node 24：`npm ci` 后运行 `npm run check`。
- Chromium：标准安装 Playwright 时运行 `npm run test:web`；也可设置 PLAYWRIGHT_MODULE_PATH 和 PLAYWRIGHT_CHROMIUM_EXECUTABLE。
- 真实 Supabase：见 [部署说明](deployment.md)。需要已登录控制台专用标签页、web-access 本地 CDP 代理及明确项目／标签页环境变量；不自动加入 CI。
- PR／主分支检查工作流已写入，但尚未在 GitHub 实际执行。
